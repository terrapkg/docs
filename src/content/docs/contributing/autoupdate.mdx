# Overview

Unlike many other package repos, most of our packages auto-update.
This means packages are bumped, rebuilt, and pushed to repos all on their own.

To do this, we use `.rhai` scripts to update packages in Terra. For more info on Rhai, check out the [Rhai] documentation.
Put your Rhai script in an `update.rhai`, in the same folder as your `.spec` and `anda.hcl`.
Andaman will detect it automatically.

<Aside type="caution">You MUST have semicolons (`;`)</Aside>

Updates are triggered every 10 minutes using <Code code={`[1;32manda[97m update`} lang="ansi" inline />.

<Aside icon="open-book">
  Actually, the [full
  command](https://github.com/terrapkg/packages/blob/4767e5b9560f2986accaeb8447fbb4ea742041cf/.github/workflows/update.yml#L27-L31)
  for auto-updating normal packages is: (as of 2024-08-09) ```sh
  RUST_BACKTRACE=full GITHUB_TOKEN=... anda update -vv --excludes nightly=1
  --excludes updbranch=1 ```
</Aside>

## Common Update Scripts

Freely copy and paste the appropriate script for your package, replacing the example.

We will only cover the most common update functions here, for a list of all possible update functions, check the [andaman custom functions documentation](https://developer.fyralabs.com/andaman/andax#custom-functions).

### GitHub Release Version Tracking

This is the most commonly used update script. It tracks the versions of a package hosted on GitHub, pulling from its releases.

```ts
// An example of AndaX update script.
rpm.version(gh("FyraLabs/subatomic")); // gets latest version from GitHub, and updates the RPM `Version:` tag.
```

Replace `FyraLabs/subatomic` with the GitHub link, minus the `https://github.com/`.

### GitHub Release Tag Version Tracking

If a project has version tags, but no releases, use the following:

```ts
// An example of AndaX update script.
rpm.version(gh_tag("FyraLabs/subatomic")); // gets latest version tag from GitHub, and updates the RPM `Version:` tag.
```

Replace `FyraLabs/subatomic` with the GitHub link, minus the `https://github.com/`.

### Generic GitLab Repo Version Tracking

To track the release versions of a package hosted on GitLab with no custom domain:

```ts
// An example of AndaX update script.
rpm.version(gitlab("43385942")); // gets latest version from GitLab, and updates the RPM `Version:` tag.
```

Replace `43385942` with the GitLab Project ID of your package.

### Generic GitLab Repo Tagged Version Tracking

To track the release versions of a package hosted on GitLab with no custom domain:

```ts
// An example of AndaX update script.
rpm.version(gitlab_tag("43385942")); // gets latest version tag from GitLab, and updates the RPM `Version:` tag.
```

Replace `43385942` with the GitLab Project ID of your package.

### Custom GitLab URL Repo Version Tracking

To track the release versions of a package hosted on GitLab with no custom domain:

```ts
// An example of AndaX update script.
rpm.version(gitlab("gitlab.freedesktop.org", "4792")); // gets latest version from GitLab, and updates the RPM `Version:` tag.
```

Replace `gitlab.freedesktop.org` with the custom GitLab domain, and `4792` with the GitLab Project ID of your package.

### Custom GitLab URL Tagged Version Tracking

To track the release versions of a package hosted on GitLab with no custom domain:

```ts
// An example of AndaX update script.
rpm.version(gitlab_tag("gitlab.freedesktop.org", "4792")); // gets latest version tag from GitLab, and updates the RPM `Version:` tag.
```

Replace `gitlab.freedesktop.org` with the custom GitLab domain, and `4792` with the GitLab Project ID of your package.

### Codeberg Repo Release Version Tracking

To track the release versions of a package hosted on codeberg:

```ts

```

Replace `ravachol/kew` with the GitHub link, minus the `https://codeberg.org/`.

### PyPi Version Tracking

To track the release versions of a package hosted on pypi:

```ts
// An example of AndaX update script.
rpm.version(pypi("qmk")); // gets latest release from pypi, and updates the RPM `Version:` tag.
```

Replace `qmk` with the package name on [pypi](https://pypi.org/).

## Nightly packages

Nightly packages are updated every 24 hours using
<Code code={`[1;32manda[97m update [0;3;37m-vv --filters[0;97;m nightly=1`} lang="ansi" inline />.
Their `anda.hcl` files should look something like this (with the `nightly = 1` label):

```hcl
project pkg {
	rpm {
		spec = "package-name.spec"
	}
	labels {
		nightly = 1
	}
}
```

Now lets go over some common nightly `update.rhai` examples.

### GitHub Commit Tracking

This is the most commonly used update script. It tracks the versions of a package hosted on GitHub, pulling from its releases.

```ts
rpm.global("commit", gh_commit("FyraLabs/subatomic")); // Grab the latest commit from GitHub, then update the globally defined RPM macro "commit"
if rpm.changed() {
  rpm.release();
  rpm.global("commit_date", date()); // Update the globally define "commit_date" to the date of the commit
}
```

Replace `FyraLabs/subatomic` with the GitHub link, minus the `https://github.com/`.

### GitLab Commit Tracking

This is the most commonly used update script. It tracks the versions of a package hosted on GitHub, pulling from its releases.

```ts
rpm.global("commit", gitlab_commit("gitlab.com", "24306684", "main"));sp
if rpm.changed() {
	rpm.global("commit_date", date());
	rpm.release();
}
```

Replace `gitlab.com` with a custom GitLab link (if there is one), replace `24306684` with the GitLab Project ID, and replace `main` with the branch to track.

### Nightly Versions of a Stable Package update.rhai

If you have a nightly version of a stable package, you will need to track commits and versions of the package.
To do this, you would use an `update.rhai` like this:

```ts
rpm.global("ver", gh("FyraLabs/subatomic")); // Track latest release version of package, update the globally defined RPM macro "ver"
rpm.global("commit", gh_commit("FyraLabs/subatomic")); // Track latest commit of package, update the globally defined RPM macro "commit"
if rpm.changed() { // This if statement updates the "commit_date", do the latest commit of a package is always the latest version that gets installed by a user
  rpm.release();
  rpm.global("commit_date", date());
}
```

## Per-branch auto-update scripts

Terra supports updating a package for specific branches instead of updating a package for all branches.
This is achieved using <Code code={`[0;3;37m--filters[0;97;m updbranch=1 [0;3;37m--labels[0;97;m branch=f41`} lang="ansi" inline /> (`f41` is replaced by the branch name).
The update command is run every 30 minutes.

The `anda.hcl` file should look like this:

```hcl
project pkg {
  rpm {
    spec = "package-name.spec"
  }
  labels {
    updbranch = 1
  }
}
```

You can obtain the branch name during runtime in Rhai using `labels.branch` (string).

<Aside type="danger">
  You MUST NOT use this feature if the script ends up bumping versions across all branches at the same time.
  This feature should only be used under cases where the version is different for different branch but for the same package.

  Consequently, under normal circumstances and without approval, you are NOT allowed to use GitHub/GitLab related functions for packages which update per branch.
</Aside>

## Weekly packages

Weekly packages are updated every 7 days using
<Code code={`[1;32manda[97m update [0;3;37m-vv --filters[0;97;m weekly=[1;35m$([1;32mdate [1;36m"+%w"[1;35m)`} lang="ansi" inline />.
Their `anda.hcl` files should look something like this:

```hcl
project pkg {
	rpm {
		spec = "package-name.spec"
	}
	labels {
		weekly = 0 # a random number between 0~6 inclusive
	}
}
```

To decide the random number, just search for "_random number between 0 and 6_" with your favourite search engine.
The random number decides which day in the week will the auto-update script run.

## Guidelines

- If possible, avoid using the `gh` and `gh_tag` version functions due to GitHub API rate limit issues. See if you can use something like crates.io, PyPi, Hackage, etc. instead.
- You might see scripts with `if filters.contains("nightly")`. This `if` statement is no longer needed.
- Avoid running code unrelated to updating/bumping packages (and in rare cases, cropping strings off the returned version) in the `update.rhai`.
