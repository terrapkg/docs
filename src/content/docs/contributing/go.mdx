<Aside title="Macro Argument Syntax" type="tip">
  All macro flags followed by `<…>` REQUIRE an argument passed to them.<br />
  All macro flags followed by `[…]` MAY have an argument passed to them.<br />
  All macro flags with `<#>` or `[#]` take only numbers as arguments.<br />
  Additionally, if there is no space between the flag `<…>`/`<#>` or `[…]`/`[#]`, you MUST NOT have a space between the flag and the argument passed to it.<br />
  Conversely, if there *is* a space you SHOULD assume the flag needs a space between them.
</Aside>

These are guidelines for packaging projects written in [Go](https://go.dev).

For the official Go language documentation, [see here](https://go.dev/doc).

Terra's Mock sandbox has networking enabled, so builders can download the dependencies directly on build time.

- You SHOULD add (at least!) the following build dependencies to your spec file:
  - <Code code={`BuildRequires: go-rpm-macros`} lang={RPMSpec} inline />
  - <Code code={`BuildRequires: go-srpm-macros`} lang={RPMSpec} inline />
- If you use `go2rpm`, you SHOULD NOT use the default naming, as an unnecessarily long package name is bad for UX. You MAY put the name generated by `go2rpm` in the <Code code={`Provides:`} lang={RPMSpec} inline /> field.
- You SHOULD remove the <Code code={`%generate_buildrequires`} lang={RPMSpec} inline /> section, and either add <Code code={`%global gomodulesmode GO111MODULE=on`} lang={RPMSpec} inline /> OR use <Code code={`%goprep_online`} lang={RPMSpec} inline /> instead of <Code code={`%goprep`} lang={RPMSpec} inline /> in the <Code code={`%prep`} lang={RPMSpec} inline /> section.
  - You SHOULD add <Code code={`BuildRequires: anda-srpm-macros`} lang={RPMSpec} inline /> to your spec if using <Code code={`%goprep_online`} lang={RPMSpec} inline />.
